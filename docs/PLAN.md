# План ядра Atari 2600 VCS для Karabas Go / Mini / Mini G

Цель: Atari 2600 VCS (6507, TIA, RIOT 6532, картриджи с переключением банков) на платах Karabas (XC6SLX25, ISE 14.7). Основа — 2600-часть ядра **k7800** ([Atari7800_MiSTer](https://github.com/MiSTer-devel/Atari7800_MiSTer), Jamie Blanks, MIT) через `sv2v`; **запасной вариант** — A2601 Retromaster в редакции [A2600Nano](https://github.com/MiSTle-Dev/A2600Nano) (VHDL, GPL v3). Из A2600Nano берём обвязку в любом случае. Файлы идут через прошивку (OSD, `FL`, `F`): загрузчика и soft-CPU в ядре нет. Репозиторий `andykarpov/karabas-go-core-atari2600`.

### Мапперы

- A2600Nano: F8 F6 FE E0 3F F4 P2 (DPC, Pitfall II) FA CV 2K UA E7 F0 32 + SuperChip. AR / 3E / SB / WD / EF / DPC+ / CDF определяются `detect2600`, но в `A2601top.vhd` у них пустые ветки.
- k7800: всё перечисленное плюс AR (Supercharger), 3E, SB, WD, EF, FA2, JANE, 0840, FC, DF, MC и др. **ARM-мапперы (DPC+, CDF, ACE — ARM7TDMI на ~70 МГц) не делаем**: как MiSTer, показываем «Out of Order». Define `NO_ARM_MAPPER` убирает только `arm_mapper_subsystem`; `mapper_dpcplus` / `mapper_cdf` / таблицы остаются — вырезать в Ф0.

### Ф0: вся машина (2026-11-11, `make atari2600-xst`)

| Часть | LUT | FF | RAMB16 | Fmax |
|---|---|---|---|---|
| `atari2600_top` (sally + TIA + M6532 + `cart2600_kg` + `detect2600`, ПЗУ / RAM картриджа снаружи) | 6325 (42 %) | 2060 | 3 | 62 МГц |

Что понадобилось для XST:
- `cart2600` → своя копия `src/rtl/karabas/cart2600_kg.sv` без ARM: DPC+ / CDF / BUS (все ревизии) и ELF дают экран «Out of Order»; нет портов DDR3 / ARM / таблиц / загрузки; у FA2 пока нет сохранения во flash (nvram читается FF). Мапперная часть и мультиплексор — текст upstream. Константы `BANK*` XST понимает, если `detect2600.sv` (там `typedef enum`) идёт в тот же запуск sv2v.
- `mos6502_ctl.sv`: ранний `return` в функции `op_a` sv2v превращает в `_sv2v_jump`, XST после этого считает `op_a` неприсвоенной и подключает к нулю (АЛУ без операций!). Переписано на `if / else` (`// karabas:`). Проверка: в `.syr` нет `Xst:653` и `_sv2v_jump` в `rtl/sv2v/`.
- `banks2600.sv`: `header_array.sum()` (Supercharger) sv2v не переводит — явная сумма; пути `$readmemh` ПЗУ AR / «Out of Order» — от `src/`.
- Выкинутые XST регистры (Xst:1710): `rreg` TIA, NMI / IRQ / SO / halt CPU (входы привязаны), старшие биты счётчиков — норма.

Верх машины `src/rtl/karabas/atari2600_top.v`: фазы CPU только от TIA (`phi0_gen` / `phi1_gen`, без `cpu_phase_controller` и MARIA); декодер 2600 (A12 — картридж, A7 — TIA / RIOT); шина с удержанием заряда и масками `oe` как в `top.sv`; сброс CPU / RIOT / картриджа держится 5 фаз после выхода TIA из сброса (делитель TIA в сбросе стоит, а sally нужны фазы, чтобы увидеть сброс); пауза — снять `tia_ce`; звук — таблица k7800. Порты: поток загрузки (для `detect2600`), `mapper_force`, ПЗУ (`rom_a` / `rom_read` / `rom_do`) и RAM картриджа (до 256 КБ) — наружу, в SRAM платы (Ф2). Симуляции ещё не было: это Ф1.

В `TIA` XST выкинул 214 бит `rreg` — неиспользуемые биты регистров чтения (коллизии), это норма. Места на LX25 хватает с большим запасом в обоих вариантах; вопрос не в объёме, а в том, переживёт ли `TIA.sv` (намеренные комбинационные петли и асинхронщина) XST / PAR / Verilator.

A2601top: единственная конструкция VHDL-2008 — `process(all)` в `A2601top.vhd` (строка 322), заменяется списком чувствительности.

## Решения

Пользователь (2026-11-11): **вариант B с откатом на A** — основа k7800, при неудаче в Ф0 / Ф1 переход на A2601 (A2600Nano). Репозиторий создал пользователь.

Предложение (ждёт подтверждения там, где помечено «?»):

1. **Основа** — rtl k7800 как есть (`src/rtl/k7800/`, без правок, коммит импорта) и его `sv2v` в `src/rtl/sv2v/` (как atarist / archie); правки для XST в исходниках с пометкой `// karabas:`. A2601 лежит рядом (`src/rtl/a2601/`) как запасной вариант и эталон для сравнения в симуляции.
2. **Свой верх машины** `atari2600_top` (Verilog-2001, `src/rtl/karabas/`): mos6502 + TIA + M6532 + cart2600 + detect2600; по образцу 2600-ветки `top.sv` k7800, без MARIA / POKEY / BIOS 7800 (режим 7800 — возможное продолжение, вариант C).
3. **Частоты.** k7800: `clk_sys` = 14,318 МГц NTSC (4 × поднесущая) / 14,188 PAL, TIA получает CE 2 × цветовой такт. У нас — одна частота платы (кратная, например 57,27 МГц = 4 × 14,318, или ближайшая доступная PLL) и дробный CE, как `archie_ce.v`: видео уходит в кадровый буфер, дрожание CE на такт ему не мешает. Точная высота звука — проверить.
4. **Картридж в SRAM** (4 МБ на всех платах) через `FL` (`/atari2600/*.a26 .bin`), до 512 КБ ROM (3E) + RAM картриджа (SuperChip, FA, E7, 3E — 256 КБ) там же или в BRAM для маленьких. Автоопределение маппера — `detect2600` при загрузке (поток байтов FL); ручной выбор маппера в OSD?
5. **Видео: кадровый буфер в BRAM** — 160 × до 256 строк × 7 бит (индекс палитры NTSC / PAL / SECAM) ≈ 18–20 RAMB16; вывод в один стандартный режим (720p60 или 800 × 600 — ?), картинка 160 → ×4 / ×5 по горизонтали, строки ×2 / ×3. Неровное число строк у игр (VSYNC в разных местах) ловит `video_stabilize` из k7800 / A2600Nano. Режим 50 Гц для PAL-игр — ?
6. **Управление.** Джойстики USB через прошивку (`kg_mcu` HID / MD2), две кнопки (Fire 2 для доработанных игр). Пэдлы — мышью (`paddles.sv` k7800; аналоговые стики — после шага 6 HID-плана прошивки). Консольные переключатели — Menu + F-клавиши (Select, Reset/Start, Color/B&W, Difficulty L/R, Pause); **F12 = сброс** (правило ядер). Клавиатурные контроллеры / Kid Vid / AtariVox — позже или никогда.
7. **Свой верх платы**, общий код через modules (`kg_mcu`, OSD, HDMI, PCM5102), Makefile как у atarist / archie. Первым — Mini G, затем Go и Mini. Mini G2: T3 = 0 (SDRAM ~CS).

## Архитектура

```
 atari2600_top ├── mos6502 (6507) ── шина 13 бит ──┬── TIA (видео, звук, входы)
 (karabas)     │                                   ├── M6532 RIOT (RAM 128 Б, порты, таймер)
               │                                   └── cart2600 (мапперы) ── SRAM: ROM / RAM картриджа ← FL + detect2600
               ├── TIA col/lum ── video_stabilize ── кадровый буфер BRAM 160×256×7 ── палитра ── вывод ── OSD ── HDMI / VGA
               ├── TIA aud0/aud1 ─────────────────────────────────────────────────── HDMI / PCM5102
               └── порты RIOT / входы TIA ── kg_mcu HID (джойстики, мышь → пэдлы, клавиши → переключатели)
```

## Фазы

Ветка и один PR на фазу, слияние в конце фазы.

- **Ф0. Импорт и fit (ветка `f0-import`) — сделано 2026-11-11**, итог выше («Ф0: вся машина»). План был: rtl k7800 (2600-часть) и A2601 без правок; `src/tools/sv2v.sh` → `src/rtl/sv2v/`; правки XST: `cart2600` (константы перечислений, вырезать DPC+ / CDF / ARM), `M6532` с `cache_ram.v`; верх машины `atari2600_top`; `make atari2600-xst` — вся машина. Критерий: собирается, нет защёлок / петель, которые ломают PAR, Fmax ≥ рабочей частоты. Иначе — откат на A2601 (`make a2601-xst` уже работает).
- **Ф1. Симуляция (ветка `f1-sim`).** Verilator: `atari2600_top` + модель SRAM картриджа, кадры PPM. Тесты: свободные тестовые ROM (TIA / HMOVE, если найдутся) и игры пользователя разных мапперов; сравнение кадров с A2601 и со Stella. Петли `TIA.sv` в Verilator — главный риск варианта B.
- **Ф2. Mini G (ветка `f2-minig`).** PLL, CE, SRAM картриджа + FL + detect2600, кадровый буфер и вывод, HDMI со звуком, HID → джойстики / переключатели, OSD. Первый запуск на плате.
- **Ф3. Мапперы и опции.** Все мапперы k7800 без ARM, «Out of Order» для ARM-игр, ручной выбор маппера, NTSC / PAL / SECAM (авто + OSD), пэдлы мышью, Fire 2, B&W, сохранение настроек в `.eep`.
- **Ф4. Go / Mini и релиз.** Верхи Go (VGA, PCM5102) и Mini, `cores.json`, README / GUIDE. Потом: аналоговые стики → пэдлы (прошивка), режим 7800 (вариант C), DB9 / физические контроллеры, если есть на плате.

## Открытые вопросы

- Имя ядра и папки: `atari2600` (`atari2600.kg`, `/atari2600`) — ?; `order` 21 — ?; репозиторий публичный — ?
- Режим вывода кадрового буфера (720p60 / 800 × 600 / 576p50 для PAL) — проверить на мониторе пользователя.
- Картридж по умолчанию (Hunchy II или пусто).
- Хватит ли одной частоты для TIA k7800 с дробным CE: в MiSTer машина целиком на `clk_sys` (14,318 / 14,188 МГц, точная дробная PLL), `clk_vid` = 4 × `clk_sys` — только видео, `clk_tia` объявлен, но не используется.
