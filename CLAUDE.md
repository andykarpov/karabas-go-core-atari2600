# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

An Atari 2600 VCS core (6507, TIA, RIOT 6532, bank-switched cartridges) for the Karabas Go, Mini and Mini G boards (Xilinx Spartan-6 XC6SLX25, ISE 14.7, XST). Base: the 2600 part of **k7800** ([Atari7800_MiSTer](https://github.com/MiSTer-devel/Atari7800_MiSTer), Jamie Blanks, MIT) through `sv2v`. **Fallback**: the A2601 of Retromaster as in [A2600Nano](https://github.com/MiSTle-Dev/A2600Nano) (VHDL, GPL v3), also the donor of the glue (`detect2600`, `video_stabilize`, the top of `upstream/a2600nano`).

Status: **Ф0 done** (branch `f0-import`): the machine `atari2600_top` = sally + TIA + M6532 + `cart2600_kg` (no ARM) + `detect2600` through sv2v, `make atari2600-xst` 6325 LUT / 62 MHz. Next **Ф1** (branch `f1-sim`): Verilator. Docs, in Russian: `docs/PLAN.md` (research, decisions, phases, open questions). Follow the phases; record a changed decision in PLAN.md.

User decisions (2026-11-11): **variant B with a fallback to A** (k7800 first; A2601 if TIA.sv / cart2600 do not survive XST, PAR or Verilator). The user created the repo. Open (ask, see PLAN.md): name / dir `atari2600` + order 21, public or not, output mode of the frame buffer, default cartridge. All file work goes through the firmware (OSD, `FL` / `F` items): no loader or soft CPU in the core. ARM mappers (DPC+, CDF, ACE) are out.

Templates: `../karabas-go-core-archie` (sv2v flow, fractional CE `archie_ce.v`, frame buffer, Makefile), `../karabas-go-core-atarist` (sv2v of a MiSTer-style core, sim harness), `../karabas-go-core-nes` (cartridge in SRAM, mappers, HID pads).

## Layout

- `docs/PLAN.md`: the plan.
- `src/Makefile`: the ISE flow as in core-archie. Now: `make atari2600-xst` (the machine alone), `make a2601-xst` (fallback machine alone), `make k7800-parts-xst` (TIA, mos6502 alone), `make <name>-report`. Board targets (`make minig`, `-xst`, `-impl`, `-core`, `-report`) wait for the board files of Ф2.
- `src/rtl/k7800/`: k7800 `rtl/` unchanged except marked edits (import commit 57680f1, upstream commit in `upstream/SOURCE.txt`); the 7800 side (Maria, Pokey, jt51 ...) is kept for a possible 7800 mode, not built.
- `src/rtl/a2601/`: the A2601 machine of A2600Nano (only edit: `process(all)` -> a list, `-- karabas:`).
- `src/rtl/sv2v/`: generated by `src/tools/sv2v.sh` (one file per module: sally / mos6502, TIA, M6532, detect2600, banks2600 mappers, mapper_fa2, cart2600_kg, spram / cache_ram) together with `src/k7800_parts.prj` and `src/atari2600.prj`: change the sources, run the script, commit all. sv2v pitfalls for XST: an early `return` in a function (`_sv2v_jump`: XST ties the function to 0, check `Xst:653`), array methods like `.sum()`.
- `src/rtl/karabas/`: our parts: `atari2600_top.v` (the machine, Verilog-2001), `cart2600_kg.sv` (cart2600 of k7800 without the ARM side, goes through sv2v); later the board tops, CE, frame buffer.
- `src/core.json`: the core file description (kgo2, `atari2600.kg`); `src/make_core.py`: symlink to `../../karabas-go-tools/make_core/make_core.py`; `src/tools/check_osd.py`: the slot check of `make core`.
- `upstream/`: `k7800/Atari7800.sv` + README + Palette, `a2600nano/` Tang Nano 20K top + README: references for the wiring, not built.
- `modules/`: the git submodule [karabas-go-modules](https://github.com/andykarpov/karabas-go-modules). Clone with `--recursive`. A change to a module is made there (branch + PR) and taken here by moving the submodule commit.

## Rules of the core

The rules of core-atarist / core-archie apply: standard video timing with syncs always present (the user's monitor rejects anything else: hence the frame buffer), `FT_CLK_OUT` about 8 MHz on Mini / Mini G, Go `FDC_*` outputs 0 when unused, OSD switch index = item position unless `"index"`, an OSD value shows 10 characters at most, FL slots 0..7 only (one array with the F slots), Verilog-2001 for XST (`sv2v` for SV), imported code marked `// karabas:`, F12 = reset (not Ctrl+Alt+Del).

- Mini / Mini G tops drive T3 (`FLASH_CS_N`) = 0: on Mini G2 it is the SDRAM ~CS.
- Games are not ours: never in the repo or the `.kg` (a free homebrew default cartridge only after its licence is checked).
- XST silently removes a register with neither reset nor initial value whose way out of idle depends on itself. When imported logic works in sim and not on the board, read the registers in the `.syr` (Xst:1710, 2404) first. The 214 trimmed `rreg` bits of TIA are unused read bits (normal).
- XST cannot map a memory written by a part-select of a wide word: one memory per byte lane.
- Tests run in seconds; simulations of minutes only after asking. Start builds / sims with `job run "<name>" -- <cmd>` + Monitor on `job watch`.
- **Ask the user before every check on the board** (and the HDMI capture), even inside a phase; the bench is shared (`hwq`). Ask before a firmware flash.
- One branch per phase of `docs/PLAN.md`, one PR at its end (create + merge after green CI allowed).
- Heavy builds: Mini G only while working on one feature, all boards for a release; map with cost table 2 first.
